# Initialization on the installed UFPR-ALPR data

The Google Drive inventory was enumerated across 150 track folders: 1,800 training images, 900 validation images and 1,800 testing images, each paired with a text annotation. This establishes metadata coverage. It does not certify that all 4,500 image files decode or that every annotation is correct.

The executed sample contains 18 actual 1920×1080 images: frames 01 and 30 of training tracks 0001/0031/0060, validation tracks 0061/0076/0090 and testing tracks 0091/0121/0150. The deterministic selection takes first, middle and last sorted tracks and is a convenience sample, not a random representative sample. Source-image and annotation hashes are retained in data/prepared/drive_init/*.epraw.json. Original image/replay bytes are not redistributed in this project package.

`scripts/initialize.py` completed for all three splits. Baseline B and pipeline D produced matching fingerprints for every frame and matching complete captured grayscale and edge bytes for all 18 images. Matching programs can still share a numerical bug; independent small-image scalar reference checks in evidence/correctness_separated_projects.json address that separate risk. These checks passed, including queue pressure and worker-failure cancellation cases.

No estimator was fitted. There are no learned weights, epochs, training accuracy or test recognition accuracy. Threshold 80 and all numerical choices were frozen before this evaluation. Annotation-derived edge occupancy and crops are descriptive diagnostics; annotations are never supplied to the benchmark kernels.

The A/B/D thread demo replays six training images for 60 frames. It records one worker identity for each sequential execution and four for D. Maximum overlapping stage wall intervals are one for A/B and four for D. Slot ownership and frame order passed. Overlap includes preemption; this is not a per-core execution trace.

The two-block, 30-frame-per-run ablation_smoke experiment validates automation only. Use results/review2_evaluation, results/review2_paced and results/review2_ram for the later repeated timing study, and read the scope in docs/REVIEW2_EVALUATION.md. Replaying images repeatedly does not increase the number of distinct source images.

Full-resolution input, grayscale, edge and annotation-crop PNGs are generated by baseline/run.py and pipeline/run.py and viewed through their outputs.html pages. Large generated captures are excluded from this download; the compact contact sheet preserves examples of actual measured outputs. Recreate the complete output set with the MSYS guide on your installed dataset.
